# Accessibility (a11y) — Shesh spec & baseline

**Status:** P2 roadmap item — now concretely specified (2026-08-13).
**Scope:** the Quickshell/QtQuick shell UI (`shesh-desktop`), CLI tools, and
voice frontend.
**Tooling:** `tools/a11y_check.py` (report-only by default; `--strict` exits 1).

## Why a11y matters here

The shell is the daily surface for Shesh: panels, toggles, dialogs, search.
Screen-reader users and keyboard-only users need labelled, focusable,
keyboard-operable elements. QtQuick exposes this through the `Accessible`
tree (`accessibleName`, `Accessible.role`, `Accessible.description`), which
Orca/AT-SPI reads on Linux.

## Concrete checkpoints (all checkable)

1. **Every interactive element has a name.** Buttons, toggles, sliders,
   text fields, menu items must set `accessibleName` (or
   `Accessible.name`). Run:
   ```bash
   python tools/a11y_check.py --root <shesh-desktop>/dots/.config/quickshell
   ```
2. **Keyboard operable.** Everything reachable with Tab; Enter/Space activate
   (QtQuick Controls give this free when using `Button`/`Switch` etc. —
   custom `MouseArea`-only widgets must add key handling).
3. **Focus visible.** `focusPolicy` + a visible focus ring (the shell's
   `FocusFrame`/ripple components already provide this on the standard
   widgets).
4. **Contrast ≥ 4.5:1** for text on backgrounds (the `Appearance` palette is
   the single source; check new colors against the light/dark themes).
5. **No text-only icons.** Icon buttons need `accessibleName` (text is not
   read by AT).

## Baseline (2026-08-13, from the checker)

- 588 `.qml` files scanned in the Quickshell tree.
- **381** interactive elements without a11y attributes.
- Fixed as the reference implementation: `killDialog.qml` (4 buttons),
  `ConfigSwitch.qml` (toggle + inner switch) — pattern:
  ```qml
  RippleButton {
      accessibleName: Translation.tr("Yes, kill")
      ...
  }
  ```
- The remaining 381 are the working backlog. Any new interactive element
  must include `accessibleName` — the checker is the review gate.

## Why not all fixed in one pass

QML cannot be rendered/validated in a CI sandbox; a mass blind edit risks
breaking the shell. The correct sequence is on-machine: run the checker,
fix file-by-file (small widgets first), then verify the shell still renders.
This spec makes that work concrete instead of vague.
